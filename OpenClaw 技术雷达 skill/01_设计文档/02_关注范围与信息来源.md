# 02 关注范围与信息来源

## 什么时候读

当讨论“什么信息应该进入技术雷达”“不同来源怎么处理”时，读这篇。

## 核心关注方向

技术雷达 Agent 只围绕用户当前主线筛选和沉淀，不追逐泛泛的 AI 热点。

当前核心方向：

- Agent 和 Harness 框架，例如 OpenClaw、Hermes 等。
- Palantir 的本体论。
- 大模型训练。
- 应用 evaluation。
- 企业交付智能化。

## 不追求泛覆盖

不建议第一版做成“所有 AI 新闻都收”的聚合工具。

需要降级或忽略的信息包括：

- 社区很热但和当前主线无关的内容。
- 只有观点没有证据的内容。
- 只适合娱乐消费、不改变技术理解的内容。
- 重复传播、没有新增信息的二手摘要。

## 信息来源

### 文章链接

- 微信公众号文章链接。
- X / Twitter 上的文章、线程或外链。
- arXiv 上的论文。
- 普通网页文章和技术博客。

### 代码仓库

- GitHub 仓库。
- GitHub README。
- GitHub docs。
- GitHub release。
- GitHub issue / PR 讨论。

### 视频内容

- YouTube 长视频。
- 技术博客视频。
- 访谈。
- 发布会。
- 教程。

## 来源处理难度

| 来源 | 自动化难度 | 第一版建议 |
| --- | --- | --- |
| 普通网页文章 | 中 | 支持 |
| arXiv 论文 | 低到中 | 支持 |
| GitHub 仓库 | 中 | 支持 README / docs / release 优先 |
| 微信公众号 | 高 | 半自动，允许手工复制原文或网页快照 |
| X / Twitter | 中到高 | 先处理单条内容和外链，不急于完整线程 |
| YouTube | 高 | 后续支持，优先 transcript，不把音频转写作为 MVP 核心 |

## 微信公众号处理原则

微信公众号文章可能存在抓取限制，第一版不要把“完全自动爬取”作为成功条件。

可接受降级方案：

- 用户手工复制正文。
- 用户保存网页快照。
- 浏览器辅助抓取。
- 只保存标题、链接、摘要和手工补充的关键段落。

## YouTube 处理原则

YouTube 长视频第一版不作为核心能力。

优先级：

1. 有 transcript 时处理 transcript。
2. 无 transcript 时先记录为 L1 / L2 信号。
3. 音频转写作为后续增强能力。
