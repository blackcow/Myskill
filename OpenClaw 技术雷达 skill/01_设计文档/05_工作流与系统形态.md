# 05 工作流与系统形态

## 什么时候读

当讨论“应该做成 skill、workflow、工具服务还是独立 Agent”时，读这篇。

## 推荐形态

不要只做成一个 skill，也不要一开始做成完整独立产品。

推荐组合：

```text
Tech Radar Skill
  -> 定义判断流程、L0-L4 分级、技术卡片、认知资产沉淀格式

Source Tools
  -> 负责抓取微信公众号、X / Twitter、arXiv、GitHub、YouTube transcript

Asset Wiki / Repo
  -> 保存 raw source、radar cards、认知资产、index、log

OpenClaw / Hermes Workflow
  -> 把上面三层串起来，形成可重复执行的 Agent 流程
```

一句话：

> skill 是脑子，工具是手，资产库是长期记忆，OpenClaw / Hermes workflow 是执行编排。

## 为什么不能只做成 skill

skill 适合定义工作协议：

- 怎么判断信息。
- 怎么分级。
- 怎么写技术卡片。
- 怎么决定是否进入资产库。

但以下内容不适合只放在 skill 里：

- 微信公众号抓取。
- YouTube transcript 获取。
- GitHub 仓库结构分析。
- X / Twitter 线程解析。
- 长期资产库索引和去重。
- 资产版本管理。

这些更适合作为工具服务、脚本或 connector。

## 推荐工作流

```text
用户输入链接 / 文本 / 仓库
-> Source Router 判断来源类型
-> Source Tool 抓取或要求用户补充原文
-> Tech Radar Skill 做分类、评分、L0-L4 分级
-> 生成 Radar Card
-> 用户确认或自动进入下一步
-> L4 写入 Asset Wiki
-> 更新 index.md / log.md
```

## 数据层建议

建议把长期资产保存在 Markdown repo 中，便于：

- 人直接阅读。
- Agent 直接编辑。
- git 记录变化。
- index / log 做轻量导航。
- 未来接入搜索、RAG 或图谱。

建议目录后续可以讨论，不在当前文档中定死。

## OpenClaw / Hermes 中的存在方式

可以拆成四个层次：

- Skill：定义判断协议和输出格式。
- Workflow：编排一次信息处理流程。
- Tool：负责来源抓取、解析、转写、仓库分析。
- Asset Repo：保存长期认知资产。

## 第一版运行方式

第一版可以手动触发：

```text
用户丢一个链接
-> Agent 处理
-> 输出重要性分级和技术卡片
-> 用户决定是否沉淀
```

不需要一开始自动监控信息源。
