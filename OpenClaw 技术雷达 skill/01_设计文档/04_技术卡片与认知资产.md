# 04 技术卡片与认知资产

## 什么时候读

当讨论“怎么把一条信息变成个人认知资产”时，读这篇。

## 核心关系

技术雷达和 LLM Wiki / 认知资产库的关系是：

```text
技术雷达负责把信息变成判断
LLM Wiki / 资产库负责把判断变成长期认知资产
```

因此第一版不应该把所有输入都写进资产库。

只有 L4 信息，或者少数需要持续观察的 L3 信息，才进入资产沉淀。

## 单条技术卡片格式

每条 L2 以上信息可以生成技术卡片。

建议格式：

```markdown
# 技术卡片：标题

## 基本信息

- 来源：
- 链接：
- 作者 / 机构：
- 发布时间：
- 信息类型：文章 / 论文 / GitHub / 视频 / 社媒
- 所属方向：
- 重要性等级：L0-L4

## 一句话判断

用一句话说明这条信息为什么值得或不值得投入注意力。

## 核心观点

- 观点 1
- 观点 2
- 观点 3

## 关键证据

- 证据 1
- 证据 2
- 证据 3

## 与我当前认知的关系

- 它补齐了什么？
- 它挑战了什么？
- 它验证了什么？
- 它和已有资产有什么关联？

## 风险和不确定性

- 不确定点 1
- 不确定点 2

## 推荐处理

- 忽略 / 记录 / 短读 / 深读 / 沉淀 / POC

## 可沉淀资产

- 技术判断：
- 认知模型：
- 架构原则：
- 评测项：
- POC 候选：
```

## 认知资产格式

L4 信息进入认知资产库时，不只是保存摘要，而是保存“可复用判断”。

建议格式：

```markdown
# 认知资产：判断标题

## 结论

一句话写清楚沉淀下来的判断。

## 适用范围

这个判断适用于哪些技术问题、场景或决策。

## 形成来源

- 来源 1
- 来源 2
- 相关技术卡片

## 推理依据

- 证据 1
- 证据 2
- 证据 3

## 对我认知的增量

说明它改变、补充或稳定了什么理解。

## 可复用方式

- 后续选型时引用。
- 后续评测时转成评测项。
- 后续 POC 时转成实验假设。
- 后续平台设计时转成架构原则。

## 仍需验证

- 待验证点 1
- 待验证点 2
```

## 资产库类型

长期资产库可以沉淀：

- 技术判断。
- 架构原则。
- 评测项。
- 工具选型依据。
- POC 候选。
- 路线候选。
- 企业交付智能化素材。
- 个人认知模型。
- 技术理解框架。

## 与 Karpathy LLM Wiki 的关系

相似点：

- 都反对临时摘要和一次性问答。
- 都强调长期沉淀。
- 都适合用 Markdown、index、log、引用证据和持续维护。

区别：

- 技术雷达是入口层，判断哪些信息值得进入资产系统。
- LLM Wiki 是沉淀层，负责组织、关联和维护长期资产。

推荐顺序：

```text
先信息过滤
再重要性分级
再技术卡片
最后认知资产沉淀
```
